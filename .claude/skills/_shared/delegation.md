# 워크플로 Step 위임 규약

각 워크플로 SKILL.md 의 **단계 구성** 표에 있는 "담당" 컬럼은 문서상 표기가 아니라
**실행 지시**다. 해당 step 은 그 에이전트에게 위임해야 한다.

## 왜 위임이 필수인가

위임하지 않고 메인 세션이 step 을 직접 수행하면 아키텍처의 핵심 세 가지가 전부 무효가 된다.

| 잃는 것 | 결과 |
|---|---|
| 모델 라우팅 | 에이전트별 tier 배정(reviewer=Haiku, architect=Opus 등)이 적용되지 않고 전 단계가 메인 세션 모델로 실행된다. 비용 설계가 무의미해진다. |
| 컨텍스트 격리 | 앞 step 의 시행착오·중간 산출물이 다음 step 컨텍스트를 오염시킨다. 특히 리뷰 단계는 구현 과정을 몰라야 Blind Hunter 가 성립한다. |
| HITL 책임 소재 | "누가 한 작업인지"가 사라져 L2 승인 대상이 모호해진다. |

## 호출 방법

Task 도구를 사용한다. `subagent_type` 은 `.claude/agents/<name>.md` 의 `name` 값이며,
스킬 디렉터리 이름(`agent-dev`)이 아니라 **접두사 없는 형태**(`dev`)다.

| 담당 표기 | subagent_type |
|---|---|
| `agent-analyst` | `analyst` |
| `agent-pm` | `pm` |
| `agent-architect` | `architect` |
| `agent-dev` | `dev` |
| `agent-qa` | `qa` |
| `agent-reviewer` | `reviewer` |
| `agent-deployer` | `deployer` |
| `agent-janitor` | `janitor` |

## 위임 프롬프트에 반드시 포함할 것

1. **해당 step 파일 경로** — 서브에이전트가 직접 읽는다. 내용을 복사해 넣지 않는다.
2. **입력 산출물의 절대 경로** — Story·ADR·이전 step 출력. 서브에이전트는 메인 세션의
   대화 맥락을 볼 수 없으므로 경로를 명시하지 않으면 찾지 못한다.
3. **로드할 PT 프롬프트 경로** — 단계 구성 표의 PT 컬럼에 있는 경우.
4. **반환 형식** — 생성·수정한 파일 경로 목록 + 완료 조건 충족 여부.

## 반환값 처리

서브에이전트의 최종 텍스트가 반환값이다. 산출물 파일은 디스크에 남으므로
**다음 step 은 경로로만 이어받는다.** 서브에이전트끼리 컨텍스트는 공유되지 않는다.

## 위임하지 않는 것

- **Phase 0 감사** — 오케스트레이터가 직접 수행한다. 무엇을 위임할지 결정하는 단계다.
- **HITL L2 승인 요청** — 사용자와의 상호작용은 메인 세션이 담당한다.

## 실패 처리

서브에이전트가 실패하거나 완료 조건을 충족하지 못하면 **해당 step 에서 중단하고
사용자에게 보고한다.** 메인 세션이 대신 수행해 메우는 조용한 폴백은 금지한다 —
위임이 무효화된 사실이 감춰진다.
